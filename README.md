# OCE Agent Conformance / Qualification OCE / Conformidad OCE

## Français

Suite de qualification externe pour une installation OpenClaw Enterprise (OCE). Elle effectue uniquement des requêtes `GET` sur l'API OCC avec deux clés de service distinctes. Elle vérifie l'accès administrateur, la séparation entre deux namespaces, la révision active, l'état d'un déploiement existant et l'observation récente de pods prêts. Une commande de sonde optionnelle vérifie un vrai tour de modèle au moyen d'un nonce. Sans cette sonde, le résultat global est `incomplete`, jamais `pass`.

La suite ne crée ni agent, ni namespace, ni déploiement. Préparez un agent déployé et un autre agent dans un namespace étranger. La clé restreinte doit pouvoir lire le premier et ne pas pouvoir lire le second. La clé administrateur doit pouvoir lire les deux, afin de prouver que l'agent étranger existe réellement. Le statut `succeeded` et un pod prêt ne prouvent pas à eux seuls qu'un modèle répond.

Copiez `config.example.json` vers un fichier de configuration privé et remplacez les identifiants. Placez les deux clés dans des fichiers distincts avec permissions `600`. `adminKeyFile` et `restrictedKeyFile` acceptent un jeton brut ou un objet JSON `{ "data": { "key": "..." } }`. `baseUrl` désigne la racine de l'API OCC, sans identifiants dans l'URL. Exécutez `node cli.js config.json report.json`. Codes de sortie : `0` réussite, `1` échec, `2` preuve incomplète. Le rapport ne contient ni clé ni contenu de réponse métier.

`probeCommand` est un tableau commande/arguments. Le placeholder `{nonce}` et la variable `OCE_PROBE_NONCE` donnent un nonce aléatoire à la sonde. Celle-ci doit faire passer ce nonce à l'agent OCE via un vrai tour de modèle et écrire sur stdout un seul JSON `{ "nonce": "...", "reply": "..." }`, avec le nonce repris dans `reply`. La suite vérifie la forme de cette réponse, mais elle doit faire confiance à la commande fournie par l'opérateur pour l'origine du tour de modèle. Le rapport `pass` n'est donc valable que si cette sonde est reliée à un vrai gateway. Ne transmettez jamais les clés comme arguments de ligne de commande.

L'adaptateur inclus `gateway-probe.js` correspond au `probeCommand` de l'exemple. Suivez le guide officiel pour ouvrir un port-forward **vers le pod de la révision active**, puis définissez `OCE_GATEWAY_PASSWORD_FILE` sur un fichier de mot de passe `600`. Le port local par défaut est `127.0.0.1:18789` ; `OCE_GATEWAY_URL` peut le modifier. L'adaptateur exige d'abord un refus sans authentification, puis envoie le nonce à `/v1/chat/completions`. La configuration du gateway doit activer cet endpoint. Sans port-forward ni mot de passe, retirez `probeCommand` et le résultat sera `incomplete`.

La CI exécute des simulations locales (`npm test`) et ne certifie aucune installation OCE réelle. Les contrôles se basent sur le [contrat OpenAPI OCC](https://github.com/openclaw/openclaw-enterprise/blob/main/packages/contracts/openapi/occ-api.openapi.json) et les guides officiels [API HTTP](https://docs-enterprise.openclaw.org/guides/http-api/) et [vérification du modèle](https://docs-enterprise.openclaw.org/guides/operate/model-verification/). Le projet est sous licence MIT.

## English

External conformance suite for an OpenClaw Enterprise (OCE) installation. It makes only `GET` requests to the OCC API with two distinct service keys. It checks administrator access, isolation between two namespaces, the active revision, an existing deployment's status, and a recent observation of ready pods. An optional probe command verifies a real model turn with a nonce. Without the probe, the overall result is `incomplete`, never `pass`.

The suite creates no agents, namespaces, or deployments. Prepare one deployed agent and another agent in a foreign namespace. The restricted key must read the first and be denied access to the second. The administrator key must read both, proving the foreign agent exists. A `succeeded` status and a ready pod alone do not prove that a model responds.

Copy `config.example.json` to a private configuration file and replace the IDs. Put the two keys in separate files with `600` permissions. `adminKeyFile` and `restrictedKeyFile` accept a raw token or JSON `{ "data": { "key": "..." } }`. `baseUrl` is the OCC API root, with no credentials in the URL. Run `node cli.js config.json report.json`. Exit codes: `0` pass, `1` fail, `2` incomplete evidence. The report contains neither keys nor business response content.

`probeCommand` is a command and argument array. The `{nonce}` placeholder and `OCE_PROBE_NONCE` environment variable provide a random nonce. The probe must send it to the OCE agent through a real model turn and print one JSON object to stdout: `{ "nonce": "...", "reply": "..." }`, with the nonce echoed in `reply`. The suite checks the response shape but relies on the operator's command for the model turn's provenance. A `pass` report is therefore meaningful only when the probe is connected to a real gateway. Never pass keys as command-line arguments.

The included `gateway-probe.js` is used by the example `probeCommand`. Follow the official guide to open a port-forward **to the active revision's pod**, then set `OCE_GATEWAY_PASSWORD_FILE` to a `600` password file. The default local port is `127.0.0.1:18789`; `OCE_GATEWAY_URL` can change it. The adapter first requires unauthenticated access to be denied, then sends the nonce to `/v1/chat/completions`. The gateway must enable that endpoint. Without a port-forward and password, remove `probeCommand` and the result will be `incomplete`.

CI runs local mocks (`npm test`) and certifies no live OCE installation. The checks follow the [OCC OpenAPI contract](https://github.com/openclaw/openclaw-enterprise/blob/main/packages/contracts/openapi/occ-api.openapi.json) and official [HTTP API](https://docs-enterprise.openclaw.org/guides/http-api/) and [model verification](https://docs-enterprise.openclaw.org/guides/operate/model-verification/) guides.
